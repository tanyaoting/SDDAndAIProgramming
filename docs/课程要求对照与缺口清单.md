## 九、仍缺、且只有你们能填的（建议按此顺序收口）

**P0 交作业前必须解决**

1. `docs/业务调研报告.docx` 封面：组号 / 组名 / 指导教师 / 完成日期 / 组长 / 组员（含本周角色）
2. 两份评审意见的**复核人**（须分别与谭垚廷、姜思远不同）
3. 角色轮换表剩下格子：第 1 / 4 周角色、姜思远的第二个角色、其他成员姓名
4. AI 日志两份的 `提示要点` 列由本人逐行核对（**不得代填**，属资格项）

**P1 影响得分**

5. 第 4 周交付：v2 验证记录、变更涟漪演练（新增考勤采集模块，含对既有契约的影响分析）、答辩材料、第 4 周 AI 日志
6. `docs/个人贡献记录.md`：支撑个人贡献系数，按「提交数 / 评审份数 / 文档章节」计量
7. 第 3 周互评仅 2 份——若为三人组，需补一份「开发 → 测试用例」评审
8. CI 位于 `.github/workflows/ci.yml`，但仓库托管在 Gitee，**Actions 不会真正触发**：要么迁到 Gitee Go，要么保留本地四门禁日志作为证据（推荐后者，附一次完整跑通记录）

**P2 可选加固**

9. 报告结论处加「三源核验」标注（规范 / 实现 / 实测截图 或 访谈原话）
10. `docs/系统设计报告.docx` §6 自查表导成 Markdown，便于教师抽查「报告与 specs 一致」
11. 若教师要求 PlantUML 而非 Mermaid，用 `npx @mermaid-js/mermaid-cli` 导 PNG 并附 PlantUML 源码
