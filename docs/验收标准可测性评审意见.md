## 3. 需约定口径（2 条）

| 标准 | 问题 | 约定口径 | 验证方式 |
|---|---|---|---|
| CS-11 单成员 ≤30s（P95，网络正常） | "网络正常"未定义，且 P95 需样本量；单样本 25.5 ms 无法证 P95 | 明确"网络正常"=各源 Mock 响应 ≤200 ms；用同一 fixture 连跑 20 次取第 19 快值作为 P95 | `perf.test.ts` 增加 20 次循环与 P95 计算；当前单次实测 25.5 ms 远低于门槛，风险低 |
| CS-13 API 调用 ≤ 速率限制 50% | "速率限制"因 Token 类型而异（GitHub 未认证 60/h、认证 5000/h），无法用固定阈值断言 | 改为可测代理指标：单次生成对 GitHub 的请求数 ≤ 20 页上限、对飞书 ≤ 页数上限；并在 `ingestion_run` 记录请求条数供审计 | 采集器分页上限用例 + 断言 `ingestion_run` 的请求计数；**不直接断言 50% 比例** |

> 两项约定均**不改变验收标准的门槛**，只是把模糊表述转为可判定的测量方法。若组内不同意该口径，须在阶段评审会上确认并回写 proposal §6。

## 4. 不可自动验证项

无。19 条标准均可转为确定性断言或上述约定口径下的测量。

## 5. 评审结论与移交

- v1 已实现 17 条的自动验证用例（见 `v1/docs/测试记录.md` §3），本评审确认其断言口径与 CS 定义一致。
- **给 v2 的建议**：CS-11、CS-13 的口径约定应在 `writing-plans` 阶段就写进计划，避免第 4 周质量数据无法对比。
- **风险提示**：CS-13 改用代理指标后，"不超过速率限制 50%"这一原始表述在字面上未被直接验证；总结报告须说明口径转换的理由，否则评审可能质疑验收缩水。
