# v2 计划文档（writing-plans 产物）

命名：`YYYY-MM-DD-<主题>.md`，一主题一文件，不复用 v1 的 tasks.md 结构。

每份计划至少包含：

1. **目标与不做什么**（范围边界先行，避免第四周才发现做多了）
2. **可用工时估算**（先算可用工时才拆任务——v1 的 123 vs 90 人时超支就是跳过了这一步）
3. **任务清单**：编号 / 交付物 / 验收标准（引用 `specs/proposal.md` 的 CS 编号）/ 依赖 / 预估
4. **TDD 顺序**：每条任务先写哪几个失败测试
5. **风险与回退**：做不成时缩哪一项，且必须回写 `specs/proposal.md` 的"不做什么"

任务编号延续 `specs/tasks.md` 的 T-0xx 序列，避免与 v1 的提交记录混淆时产生歧义。
