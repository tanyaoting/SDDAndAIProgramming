# 第 3 周 · 方法切换回顾（15 分钟素材）

> 指导书第 3 周步骤 1：对照第 1–2 周 SDD 体验，写下 Superpowers 与 SDD 各自的优势、局限与适用场景（各一条即可），供项目总结报告「过程回顾」章使用。  
> 日期：2026-11-26　阶段：进入 v2 前

## Superpowers

| 维度 | 内容 |
|---|---|
| **优势** | 把「澄清 → 计划 → 红绿 TDD → 调试 → 评审」固化成可触发的技能链，提交历史上能直接看见测试先行，适合从零重做时防止跳步。 |
| **局限** | 流程 intermediate 产物多（plans/reviews/红绿成对提交），若组内不坚持互评与站会，容易只剩代码绿、过程证据空。 |
| **适用** | 已有较清晰契约、需要证明「另一套工作流也能做出同等质量」的重写或对照实验（本课程阶段二）。 |

## SDD（第 1–2 周）

| 维度 | 内容 |
|---|---|
| **优势** | 先把 proposal/design/tasks 写成唯一事实来源，再生成代码，范围与 ADR 可审查、可复现，适合「想清楚再做」的第一遍。 |
| **局限** | 规范写厚后易诱导向「按任务清单一次性生成大块实现」，红绿痕迹与互评纪律不如 Superpowers 强制。 |
| **适用** | 需求与架构尚未稳定、必须先冻结契约与验收标准的启动周（本课程阶段一）。 |

## 切换结论（一句话）

阶段一用 SDD 把「做什么」钉死；阶段二用 Superpowers 在同一契约下证明「怎么做」可换方法复现——对比的是工作流与证据形态，不是两套产品。
